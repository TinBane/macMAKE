# macMAKE v0.1.1 — Linux Release

macMAKE v0.1.1 updates the Linux-native Classic Macintosh development toolchain with seven major release enhancements, verified Mac OS 9.2.2 runtime acceptance, independent native Motorola 68000 application building, external Rust/XCOFF interop, CodeWarrior XML importing, profile-driven QEMU emulation, and full telemetry opt-out.

## User-Facing Overview

### What macMAKE does

macMAKE enables developers on Linux x86-64 workstations to build authentic Classic Macintosh applications without vintage hardware or emulation during the build phase. It parses CodeWarrior-style project configurations, compiles C source code with bundled GNU toolchains, resolves CFM/PEF linking natively, generates Macintosh resource forks, applies Finder metadata, and packages final applications into MacBinary II (`.bin`) archives ready for transfer to Classic Mac OS.

### Summary of the seven improvements

1. **Installer and First Application**: Aligned case-sensitive paths with the `macMAKELibs` layout (`MSL_C/MSL_MacOS/Lib/PPC/MSL_C_Carbon.Lib`, `MSL_Runtime_PPC_D.Lib`, `MSL_Extras/MSL_MacOS/Lib/PPC/MSL_Extras_Carbon.Lib`), ensuring seamless automated installation and incremental rebuilds.
2. **Streamlined SDK Setup**: Added `macmake sdk fetch --minimal` using sparse git checkout to retrieve the pinned Universal Interfaces subset with SHA-256 validation, plus verified local MSL helper scripts.
3. **Independent Native Motorola 68000 Application Backend**: Bundled GNU GCC 12.2.0 and GNU Binutils 2.46.1 for target `m68k-unknown-elf`, building bounded C89 applications with CODE 0/1 segments, Toolbox veneers, Finder metadata, and MacBinary II packaging without Retro68. Includes a sequenced OS roadmap.
4. **External Rust-to-Classic XCOFF Interop**: Added `examples/classic-rust-interop`, demonstrating consumption of big-endian PowerPC XCOFF objects emitted by external pinned Rust nightly (`powerpc-apple-macos.json`), with macMAKE handling native CFM/PEF linking, resources, and MacBinary packaging.
5. **CodeWarrior XML Import & Classilla Build Boundary**: Added `macmake import-cw-xml` feature matrix and practical workflow guide in `docs/codewarrior-xml-and-classilla.md` for converting historical XML project exports into `macmake.toml`. Documented the Classilla 128-target inventory and package assembly boundaries.
6. **Optional Emulator Execution (`macmake run`)**: Added profile-driven QEMU Mac OS 9.2.2 runner with copy-on-write disk protection, P6 PPM screenshot capture and validation, and structured run reports.
7. **Analytics Opt-Out**: Provided complete telemetry opt-out via `--no-analytics` installer flag, `MACMAKE_DISABLE_ANALYTICS=1` environment variable, and persistent configuration preference marker.

### Support boundaries and plain-language limitations

- **Supported Workflow**: Linux x86-64 host → Classic Mac OS 9 PowerPC CFM/PEF applications, primarily C.
- **Experimental Features**:
  - Native M68000 application output is limited to C89, one near-model CODE 1 segment, CODE 0 jump table/startup, bounded PC-relative file-backed data, and no external linked libraries. Multi-segment architectures, A5-relative global data, and CFM-68K are not supported.
  - Rust interop demonstrates external toolchain integration. macMAKE does not bundle `rustc` or compile Rust source directly.
  - C++ support is preview-only without Itanium ABI runtime parity, exceptions, or standard library support.
- **Third-Party Materials**: Apple Universal Interfaces and Metrowerks MSL are proprietary historical files and are not redistributed with macMAKE. Users must supply files they are authorized to use.
- **Unsupported in v0.1.1**: CFM-68K, full Classilla clean rebuild, Mac OS X / Mach-O, macOS host platforms.

### Working examples and how to run them

1. **PowerPC C First App** (`examples/first-app/`):
   ```sh
   macmake sdk fetch --minimal
   macmake sdk add "$HOME/.local/share/macmake/macMAKELibs/Universal" --id macos9-sdk
   ./setup-user-msl.sh "$HOME/.local/share/macmake/macMAKELibs"
   macmake doctor . --target "Classic PPC C"
   macmake build . --target "Classic PPC C"
   ```
2. **Native 68K HelloWindow** (`examples/first-app/hello-window-68k/`):
   ```sh
   macmake inspect .
   macmake doctor . --target "Classic 68K Mac OS 8.1"
   macmake build . --target "Classic 68K Mac OS 8.1"
   ```
3. **Rust XCOFF Interop** (`examples/classic-rust-interop/`):
   ```sh
   ./build-rust.sh
   macmake doctor . --target "Classic PPC Rust Interop"
   macmake build . --target "Classic PPC Rust Interop"
   ```

## Developer-Facing Technical Specification

### Exact compiler profiles and target formats

- **PowerPC CFM/PEF**:
  - Compiler profile: `classic-ppc-xcoff-c-v1` (or `cw8-os9-carbon-ppc-c-v1-preview`)
  - Target: `powerpc-unknown-macmake`, producing big-endian 32-bit PowerPC XCOFF objects.
  - Runtime profiles: `codewarrior-msl-compatible`, `macmake-classic-c-v1`.
  - Output: PEF (Preferred Executable Format) container with code/data sections, loader relocation blocks, transition vectors, and CFM export/import libraries.
- **Motorola 68000 Segmented**:
  - Compiler profile: `classic-68k-segmented-app-c-v1`
  - Runtime profile: `macmake-classic-m68k-c-v1`
  - Target: `m68k-unknown-elf`, baseline M68000 instructions (`-m68000`).
  - Output: Classic Mac OS segmented CODE resources:
    - `CODE 0`: Jump table header, above-A5 size, below-A5 size, jump table entries.
    - `CODE 1`: Entry point, application code, near-model data references.
    - Resource fork packed with `cfrg`, `SIZE`, and custom icon/dialog resources.

### PowerPC ABI and CFM/PEF outputs

- PowerPC Calling Conventions: System V PowerPC / AIX calling conventions adapted for Classic Macintosh runtime. Transition vectors (TVs) with function code pointer and TOC anchor (r2).
- Section placement: Code (`.text`), read-only data (`.rodata`), writable data (`.data`), zero-initialized BSS (`.bss`).
- Relocation processing: Linker normalizes and resolves `R_PPC_ADDR32`, `R_PPC_ADDR16_LO`, `R_PPC_ADDR16_HA`, `R_PPC_REL24`, `R_PPC_REL32`.
- PEF Generation: Validated section headers, packed loader relocation instructions, import library fragment bindings, and export transition vectors.

### Experimental CODE 0/1 application constraints

- Near-model addressing: Jumps and data references must fit within 16-bit signed offsets (`[-32768, +32767]`).
- Segment layout: CODE 0 contains 16-byte jump table header plus jump table entries; CODE 1 contains startup entry and all code.
- File-backed PC-relative data: Constants and initializers are placed within the CODE 1 segment; general A5-world global data allocation is not implemented in v0.1.1.
- Veneers: In-process Toolbox traps (`_WaitNextEvent`, `_NewWindow`, `_DrawString`, etc.) handle A-line trap emission and 68K Pascal calling convention conversions.

### Rust-to-XCOFF integration and compiler prerequisites

- Pinned toolchain: `rustc 1.70.0-nightly` (commit `2036fdd24`, 2023-03-27), `nightly-2023-03-28`.
- Target definition: `powerpc-apple-macos.json` (32-bit big-endian AIX XCOFF, `powerpc-ibm-aix`).
- Compilation command: `cargo build -Zbuild-std=core --target powerpc-apple-macos.json --release`.
- ABI constraint: Scalar and pointer arguments follow C ABI; by-value aggregate structs exhibit ABI divergence between Rust's AIX-derived layout and Macintosh C layout. Use pointer parameters or C wrappers for structs.

### C and C++ compatibility distinctions

- C: Supported C89/C99 compilation with Classic Macintosh type sizes and structure alignment (`#pragma options align=mac68k` / `power`).
- C++: Experimental preview only. GNU C++ frontend compiles syntax, but Itanium ABI name mangling diverges from Metrowerks C++ ABI. RTTI, exception handling (`__throw`), and `libstdc++` runtime routines are not provided.

### CodeWarrior XML feature matrix

- Documented in `docs/codewarrior-xml-and-classilla.md`:
  - Project structure and targets: Supported.
  - Source file membership and access paths: Supported.
  - Ordered link libraries (`.lib`, `.shlb`): Supported.
  - Binary `.mcp` files: Unsupported (requires CodeWarrior XML export).
  - Proprietary compiler pragma emulation: Partial.

### Classilla build-evidence boundaries

- Target inventory: 131 configured entries (129 native targets, 2 non-native).
- Tested outputs: 128 native targets successfully compile to objects/libraries under authorized local environments.
- Assembly: 92 PEF containers and fragment registries validated.
- Support boundary: Full-browser clean rebuilding and Mac OS runtime execution of the complete Classilla suite are not qualified or supported in v0.1.1.

### QEMU runner profile, screenshots, and operator checkpoints

- Runner command: `macmake run --profile qemu-macos9 --artifact <path>`.
- Profile: QEMU `mac99`, PowerPC G4, GTK display, Mac OS 9.2.2 base disk.
- Disk safety: Ephemeral `qcow2` copy-on-write overlay; base image opened strictly read-only.
- Screenshots: QMP `screendump` captured as P6 PPM; header, dimensions (800×600), RGB byte count (1,440,000), and SHA-256 validated at `guest_boot` and `application_state` checkpoints.
- Observed issue: Console prompt prints on each 250ms polling timeout while awaiting input. Documented nonblocking defect.

### Build-evidence files and independent artifact inspection

- Built artifacts are independently inspectable with:
  ```sh
  macmake inspect-artifact <pef-file> --resource-fork <rsrc-file> --finder-info <finf-file> --json
  ```
- Validates:
  - PEF container header, section count, loader section, import/export symbols.
  - Resource fork map, type list, reference list, data offsets.
  - Finder info creator/type codes, flags, window position.
  - MacBinary II header checksum (CRC) and fork sizes.
